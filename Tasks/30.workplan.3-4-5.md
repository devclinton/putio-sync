## Task 3: Update API Route Structure

### Current State
- Basic API routes exist in putio-sync-api
- Routes may not be comprehensive
- Structure may not follow REST conventions

### New Route Structure

#### Put.io Proxy Routes
```
/putio/files
  GET  /               - List files for folder (supports sorting)
  GET  /:id            - Get file details
  DELETE /:id          - Delete file/folder (recursive optional)
  GET  /:id/download   - Get download URL

/putio/transfers
  GET  /               - List all transfers
  POST /               - Add transfer (multipart for .torrent, JSON for magnet)
  GET  /:id            - Get specific transfer stats
  DELETE /:id          - Remove transfer
  POST /:id/start      - Start/resume transfer
  POST /:id/stop       - Stop transfer
```

#### Local Operations Routes
```
/local/files
  GET  /               - List files in download folder
  GET  /*path          - Get info on specific file
  DELETE /*path        - Delete local file

/local/transfers
  GET  /               - List local torrent transfers
  POST /               - Add transfer (multipart/.torrent or JSON/magnet)
  DELETE /*path        - Remove transfer
  POST /*path/start    - Start transfer
  POST /*path/stop     - Stop transfer

/local/queue
  GET  /               - Get current download queue
  PUT  /               - Update entire queue
  POST /*path/move_up      - Move item up in queue
  POST /*path/move_down    - Move item down in queue
  POST /*path/move_first   - Move item to first position
  POST /*path/move_last    - Move item to last position
  POST /*path/skip         - Skip item in queue
```

#### System Routes
```
/settings
  GET  /               - Get current settings
  PUT  /               - Update settings

/stats/downloads       - Statistics about past downloads
/stats/transfers       - Statistics about current transfers
/stats/disk           - Disk space information

/history              - Download history with status
```

## Task 5: Update Daemon to Use API's Download Manager

### Current State
- Daemon creates its own download manager
- No integration with API server
- Duplicate download logic

### Changes Required

1. **Detect API Mode**
   ```rust
   pub struct DaemonConfig {
       // ... existing fields ...
       api_enabled: bool,
       api_url: Option<String>,
   }
   ```

2. **Conditional Download Manager**
   - If API enabled: Use API endpoints for downloads
   - If API disabled: Create own DownloadManager (current behavior)

3. **API Client Mode**
   ```rust
   enum DownloadMode {
       Local(DownloadManager),      // Direct manager
       Remote(ApiClient),            // Through API
   }
   ```

4. **Update Daemon Logic**
   - Check API availability
   - Route download requests appropriately
   - Handle API failures gracefully

5. **Shared Queue**
   - Use same database for queue
   - Ensure queue sync between daemon and API
   - Handle concurrent access

### Implementation

```rust
impl PutioDaemon {
    pub async fn initialize(&mut self) -> DaemonResult<()> {
        if self.config.api_enabled {
            // Use API for downloads
            self.download_mode = DownloadMode::Remote(
                ApiClient::new(&self.config.api_url?)
            );
        } else {
            // Create own download manager
            self.download_mode = DownloadMode::Local(
                DownloadManager::new(download_config)
            );
        }
        // ...
    }

    async fn download_file(&self, file: &FileEntry) -> DaemonResult<()> {
        match &self.download_mode {
            DownloadMode::Local(manager) => {
                manager.download_file(file, None).await?;
            }
            DownloadMode::Remote(client) => {
                client.post("/local/downloads", file).await?;
            }
        }
        Ok(())
    }
}
```
