**Status: IN PROGRESS**

- ⏳ Final testing and documentation - TO DO

## Overview

This workplan details the restructuring of the putio-sync project from a monolithic `putio-sync-core` crate into multiple specialized crates with the `putio-sync-*` naming convention. The restructuring includes:

- Splitting `putio-sync-core` into 4 specialized crates
- Removing chunking functionality entirely
- Adding dedicated daemon crate
- Enhancing magnet file support throughout
- Renaming functions for clarity
- Reorganizing code within modules

## Current Structure

**Existing Workspace:**
- `putio-sync-core` - Monolithic core library (api, db, download, config, sync, filtering, etc.)
- `putio-sync-cli` - CLI application with commands, watch, daemon
- `putio-sync-api` - REST API server

**Total:** 3 crates

## Target Structure

**New Workspace:**
- `putio-sync-client` - Pure API client (extracted from core/api)
- `putio-sync-db` - Database layer (extracted from core/db)
- `putio-sync-download` - Download management (extracted from core/download)
- `putio-sync-file-manager` - File watching and torrent management (extracted from cli/watch)
- `putio-sync-api` - REST API server (existing, updated dependencies)
- `putio-sync-daemon` - Daemon orchestration (new, extracted from cli/commands/daemon)
- `putio-sync-cli` - CLI commands (existing, slimmed down)

**Total:** 7 crates

## Risk Assessment

### High Risk Changes

1. **Chunking Removal**:
   - **Risk**: Breaking resume functionality if not properly replaced
   - **Mitigation**: Ensure streaming download has resume capability
   - **Verification**: Test download interruption and resume

2. **Crate Splitting**:
   - **Risk**: Circular dependencies between crates
   - **Mitigation**: Careful dependency planning (client → db → download → cli/api/daemon)
   - **Verification**: Check with `cargo tree`

3. **Daemon Restructuring**:
   - **Risk**: Breaking hot-reload functionality
   - **Mitigation**: Careful extraction preserving state management
   - **Verification**: Test config changes during daemon operation

### Medium Risk Changes

1. **Function Renames**:
   - **Risk**: Missing renames in some files
   - **Mitigation**: Use IDE refactoring tools, grep for old names
   - **Verification**: Full text search for old function names

2. **Module Moves**:
   - **Risk**: Missing imports in updated files
   - **Mitigation**: Compile after each move, fix errors immediately
   - **Verification**: `cargo check` after each module move

### Low Risk Changes

1. **Adding new methods**: Low risk, purely additive
2. **Documentation updates**: No functional impact
3. **Code formatting**: No functional impact
