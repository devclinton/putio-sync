# Research: Web UI Redesign with Themes

## R1 Visual direction

- **Decision**: Direction B, "Tinted": a sidebar with icons on desktop, a bottom tab bar on
  phones, neutrals tinted by the accent, sentence-case card titles, large page titles, soft
  shadows, 20 px card corners, pill badges.
- **Rationale**: picked by the user from two prototypes rendered on the real pages
  (Quiet: top bar with segmented nav; Tinted). Tinting makes an accent change the whole feel,
  which is the "charm" part of the brief.
- **Alternatives**: A "Quiet" (smaller change, less character).

## R2 Mode switching

- **Decision**: define every colour once as `light-dark(light, dark)`. `<html>` carries
  `color-scheme: light dark` by default; `data-mode="light"` / `"dark"` forces
  `color-scheme: light` / `dark`.
- **Rationale**: one definition per token instead of a media-query copy and a forced-dark copy
  (three copies otherwise). Saves ~3 KB and removes drift between copies.
- **Alternatives**: `@media (prefers-color-scheme)` plus `[data-mode]` duplicates (bigger,
  error-prone). Support: Chrome 123, Safari 17.5, Firefox 120 (all 2024). An older browser drops
  every `light-dark()` declaration, so it shows its default black text on white: plain but
  readable. A custom property cannot carry a fallback for an unsupported value.

## R3 Accent themes

- **Decision**: seven accents: blue (default), indigo, teal, green, orange, pink, graphite.
  Each is a `[data-accent=name]` rule setting bg, surface, surface-2, line, text, muted, accent
  and on-accent. Values are generated by `themes.py`, which tints neutral bases in OKLab (keeps
  lightness, takes a few percent of the accent's chroma) and fails on any AA miss.
- **Rationale**: precomputed hex values make the contrast checkable by a plain test and avoid
  relying on `color-mix()` for text colours. Light accents carry white text; dark accents carry
  a near-black tinted text.
- **Alternatives**: runtime `color-mix()` for the tint (smaller but untestable without a CSS
  engine); a free colour picker (cannot guarantee contrast).

## R4 Applying the choice before first paint

- **Decision**: `ui/theme.js`, a classic (non-module) script in `<head>`, reads
  `localStorage["putio-sync.appearance"]` (`{"mode":"system|light|dark","accent":"blue"}`),
  sets `data-mode` / `data-accent` on `<html>`, and exposes `window.appearance = { get, set }`.
- **Rationale**: module scripts are deferred and would paint once with the default theme. The
  index must not hold inline scripts (`index_has_no_inline_script` test), so it is a file.
- **Alternatives**: a cookie read by the server (sends UI state to the daemon; spec forbids).

## R5 Navigation and icons

- **Decision**: keep the existing `<header class="topbar">` markup. CSS turns it into a fixed
  sidebar above 600 px and, at 600 px and below, a compact top row (brand, mode toggle, sign out)
  plus a `position: fixed` bottom tab bar for `#nav`. Icons are CSS masks over a `--icon`
  property set per `[data-page]`, with a generic icon as default.
- **Rationale**: no JS change to the router; other features add `<a data-page="x">` and get the
  generic icon, or set `--icon` for their own.
- **Alternatives**: inline SVG in the HTML (more bytes, more markup per page link).

## R6 Contrast test in `make ci`

- **Decision**: a test in `tests/ui_assets.rs` fetches `/assets/app.css`, collects every
  `--name: light-dark(#a, #b)` declaration per rule (`:root` and each `[data-accent]`), resolves
  accents over `:root`, and checks text, muted, accent and the status colours against bg,
  surface and surface-2, plus on-accent on accent, at 4.5:1, in both modes.
- **Rationale**: the constitution makes `make ci` the gate; the generator alone could drift
  from hand edits.

## R7 Charts

- **Decision**: Stats already draws SVG with CSS classes. Point `--chart-1` at `--accent`,
  derive `--chart-1-on` and the heatmap steps with `color-mix(in oklab, var(--accent) N%,
  var(--surface))`.
- **Rationale**: no JS change; the charts follow mode and accent automatically.

## R8 Motion

- **Decision**: one entrance on route change (content fades and rises 6 px over 180 ms), toasts
  slide in, the dialog scales in, nav highlight and buttons transition colour. All inside
  `@media (prefers-reduced-motion: no-preference)`.
- **Rationale**: the frontend-design guidance: one orchestrated moment, motion that answers an
  action; nothing loops.

## R9 Fonts

- **Decision**: system stack (`-apple-system, BlinkMacSystemFont, "SF Pro Text", system-ui,
  "Segoe UI", Roboto, sans-serif`), tabular numerals for figures, a monospace stack for paths.
  Type scale: 13 / 15 / 17 / 22 / 34 px with tight tracking on titles.
- **Rationale**: San Francisco on the user's Apple devices gives the Apple feel for free; web
  fonts would cost 20–40 KB of the budget.
